CORE MODULES

FIVE SYSTEMS. ONE GOAL: SHIP.

Scrumb operates as a state machine for project birth and survival. These are the modules it runs.

scrumb — module.list —all
  • 01 ARCHITECT_AUDIT No vague descriptions. Scrumb fires a technical MCQ interview at your idea — locking in tech stack, team skills, and scope before any tasks are created. "Build a bus app" doesn't compile here.
  • 02 DAG_GENERATOR Outputs a Directed Acyclic Graph of tasks. Every task knows its parent, its assigned owner (matched to team skills), and its hard dependencies. No flat to-do lists. Real architecture.
  • 03 PANIC_MODE When deadline math fails, Scrumb automatically archives non-critical tasks to guarantee a working MVP ships on time. Scope is trimmed by the AI — not discovered missing at 2am on submission day.
  • 04 SHAME_ENGINE Analyzes stalled tasks. Identifies blockers by name. Generates brutal but funny accountability reports to restore momentum. Annoying by design. Effective by necessity.
  • 05 INTEGRITY_GUARD Cheating detector. Blocks marking a parent task "Done" if sub-tasks are still open. Your dashboard reflects reality — not the story you tell yourself at 11pm.

THE SHAME ENGINE

When someone hasn't touched their task in 48 hours and the deadline is Friday, Scrumb stops being polite. It generates an accountability report. By name.

// AUTO-GENERATED — SCRUMB SHAME REPORT — T-MINUS 36HRS

@Rohan — task status: STALLED (52 HRS)
Assigned: [ backend/auth/jwt-middleware ]
Impact: BLOCKING 4 downstream tasks. Sprint is dead if this doesn't merge today.

IDE activity detected: 11 sessions since Monday.
Commits pushed: 0
YouTube watch time estimate: non-zero.

// RECOMMENDATION: Close the system design video.
// Open the file. Write the function. It is 40 lines.
// You have done harder things. Do this one.

Opt-in per team. Togglable per sprint. Ruthlessly effective at eliminating drift in small dev teams where social accountability is the only real enforcement mechanism.
