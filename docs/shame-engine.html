SYSTEM MODULE — SHAME_ENGINE v1.0

THE SHAME
ENGINE

Annoying by design. Effective by necessity.

Small teams run on social accountability. When a critical-path task hasn't moved in 48 hours, the polite approach has already failed. Scrumb's Shame Engine generates named, task-specific accountability reports to restore momentum — before the deadline becomes a casualty.

SCENARIO A

THE GHOST

Team member assigned a task. Has not updated it, responded to pings, or committed any code. Deadline is approaching. The Shame Engine drafts a report with full stall metrics and downstream impact. Delivered to the team channel.

SCENARIO B

THE SCOPE CREEP

Someone marked their core task "done" and started building an unrequested feature. Integrity Guard fires first, blocking the premature completion. Shame Engine notes the distraction in the activity log and flags it in the next report.

SCENARIO C

THE OPTIMIST

Team member estimated 2 hours. It's been 9. They insist they're "almost done." The Shame Engine doesn't argue — it just updates the downstream impact calculation and shares it with the team so everyone can see the math.

SCENARIO D

THE LEGITIMATE BLOCKER

Task is stalled because it depends on someone else's unfinished work. The Shame Engine correctly identifies the root blocker and redirects the report to the upstream owner. The stalled developer is cleared. The actual problem is surfaced.

HOW IT WORKS

THE MECHANICS

The Shame Engine isn't random. It follows a specific detection and escalation logic.

  • 1

    STALL DETECTION

    Scrumb monitors task status against elapsed time. When a task — especially one on the critical path — exceeds its stall threshold without a status update or commit, the Shame Engine begins composing a report.

  • 2

    ROOT CAUSE ANALYSIS

    Before generating the report, Scrumb checks whether the stall is caused by a legitimate upstream dependency. If so, the report is redirected to the actual blocker. Innocent parties are not shamed.

  • 3

    IMPACT CALCULATION

    The report includes a live downstream impact assessment: how many tasks are blocked, and what the cascade looks like if the stall continues through the deadline.

  • 4

    REPORT GENERATION

    The AI generates a specific, named, task-level accountability message in plain English. It is designed to be direct, factual, and — critically — a little funny. Nobody ignores it.

  • 5

    DELIVERY & RESOLUTION

    The report is delivered to the team channel or IDE. Once the task resumes and a commit is pushed, the Shame Engine marks the incident resolved and stops escalating.

CONFIGURATION

IT'S CONFIGURABLE

The Shame Engine is opt-in per team and tunable per sprint. Adjust the thresholds, tone, and delivery method.

SHAME_ENGINE
ENABLED
Toggle the entire module on or off per team. Off by default — teams activate it intentionally.
STALL_THRESHOLD
48 HRS (default)
How long a task must stall before a report is generated. Adjustable per sprint urgency.
CRITICAL_PATH_ONLY
OFF (default)
When on, only tasks on the critical path trigger shame reports. Useful for less aggressive teams.
TONE
BRUTAL_FUNNY
Report tone. Options: BRUTAL_FUNNY (default), DIRECT, PROFESSIONAL. All are honest.
DELIVERY
TEAM_CHANNEL
Where the report is sent. Team channel (maximum social pressure) or private DM (gentler).
SELF_SHAME
ENABLED
When on, team members can trigger a shame report on themselves as a forcing function.
