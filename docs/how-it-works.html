THE EXECUTION PIPELINE

Scrumb operates as a state machine for project birth and survival. Your project cannot advance until each stage clears. Five gates. One output: shipped.

PIPELINE OVERVIEW

THE FIVE STAGES

Scrumb operates as a state machine for project survival. Your project cannot advance to the next stage until the current one clears. No shortcuts. Here's exactly what happens at each gate.

01
ARCHITECT_AUDIT

THE ARCHITECT AUDIT

Before a single task is created, the Architect Prime AI interrogates your idea. You describe the project. Scrumb responds with technical multiple-choice questions that surface every assumption your team hasn't articulated yet.

Stack choices get locked. Team skill levels get logged. MVP scope gets bounded. The questions are uncomfortable on purpose — "we'll figure it out" is how projects fail at hour 36 of a 48-hour hackathon.

// EXAMPLE AUDIT EXCHANGE
ARCHITECT_PRIME: "For your backend, which matches your team's experience?"
  A) FastAPI + SQLite (familiar, fast)
  B) Django REST + PostgreSQL
  C) Express.js

USER: A

// Stack locked. Generating task tree for FastAPI architecture...
02
DAG_GENERATOR

DAG GENERATION

Based on the audit, Scrumb generates a Directed Acyclic Graph of every task. Every task knows what it depends on, what depends on it, and who owns it. Owners are auto-assigned from the skill matrix.

[ setup/db-schema ] → [ backend/user-auth ] → [ backend/api/endpoints ]
                                   ↓
                  [ frontend/dashboard ] — BLOCKED

Owner: @Rohan · Est: 3hrs · CRITICAL PATH
03
ACTIVE_BUILD

ACTIVE BUILD

Your team is building. Scrumb surfaces the task tree directly inside your JetBrains IDE. Each developer sees their tasks, their blockers, and the downstream impact if they fall behind.

The Integrity Guard runs continuously. You cannot mark a parent task complete while its sub-tasks are still open. The dashboard always reflects reality. See the JetBrains plugin →

04
DRIFT_DETECTION

DRIFT DETECTION

Panic Mode activates when scope exceeds timeline. It archives non-critical tasks so the MVP can still ship on time.

The Shame Engine activates when a specific task has stalled too long on the critical path. It generates a named accountability report directed at the responsible person. Full Shame Engine docs →

05
MVP_SHIPPED

MVP SHIPPED

The project compiles. Not necessarily perfect — but finished, functional, and defensible. Scrumb generates a post-project report: what shipped, what was archived, where time was lost, and the team's real velocity.

// BUILD COMPLETE
Tasks completed: 34/34 · Archived (Panic Mode): 8
Shame Engine activations: 2 · Deadline: MET ✓
